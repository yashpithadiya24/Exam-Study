1. Greedy Algorithm શું છે?

Greedy algorithm દરેક step પર તે સમયે સૌથી સારી લાગતી પસંદગી કરે છે (locally optimal choice), આશા રાખે છે કે અંતે global optimal answer મળશે. પસંદ કરેલી વસ્તુ સામાન્ય રીતે પાછી કાઢાતી નથી.

Solution function

પસંદ કરેલા items solution આપે છે કે નહીં તે તપાસે.

Feasible function

પસંદગી constraintsનું પાલન કરે છે કે નહીં.

Selection function

આગળનો સૌથી promising candidate પસંદ કરે.

Objective function

Solutionનું value/cost માપે છે.

યાદ રાખો: Greedy હંમેશાં optimal નથી. તે ખાસ ત્યારે વિશ્વસનીય છે જ્યારે problemમાં greedy-choice property અને optimal substructure હોય.

2. Make Change Problem

લક્ષ્ય amount માટે ઓછામાં ઓછા coins/notes પસંદ કરવા. Greedyમાં દરેક વખતે amountમાં ફિટ થાય તેવો સૌથી મોટો denomination પસંદ કરીએ.

ઉદાહરણ: denominations {10, 5, 2, 1}, amount 28 → 10+10+5+2+1 = 5 coins.

આ પદ્ધતિ દરેક denomination systemમાં minimum coins આપતી નથી. અહીં દર્શાવેલા standard denominations માટે તે યોગ્ય છે.

3. Minimum Spanning Tree (MST)

Connected, weighted, undirected graphનું spanning tree દરેક vertex જોડે છે, cycle નથી બનાવતું અને V vertices માટે તેમાં V−1 edges હોય છે. MST એ સૌથી ઓછા કુલ weightવાળું spanning tree છે.

Kruskal’s Algorithm

  1. બધી edgesને weight પ્રમાણે વધતા ક્રમે sort કરો.
  2. સૌથી નાની edge લો, પણ cycle બને તો reject કરો.
  3. V−1 edges પસંદ થાય ત્યાં સુધી ચાલુ રાખો.

Interactive Kruskal example

Edges: AB=1, BC=2, AC=3, BD=4, CD=5. Cycle ન બને તેવી સૌથી નાની edges પસંદ કરો.

Kruskal time: O(E log E) · Space: O(V + E)

Prim’s Algorithm

કોઈ એક vertexથી શરૂ કરો. હાલના treeમાંથી બહારના vertex સુધી જતી minimum-weight edge પસંદ કરો. બધા vertices જોડાય ત્યાં સુધી ચાલુ રાખો.

PointKruskalPrim
શરૂઆતબધી edges sortએક vertex
પસંદગીGlobal minimum edge, cycle નહીંTreeની boundary પર minimum edge
Common goalMST, કુલ V−1 edges
Typical complexityO(E log E)Min-heap + adjacency list: O(E + V log V)

4. Dijkstra’s Single Source Shortest Path

એક sourceથી દરેક vertex સુધી shortest distance શોધે છે. દરેક iterationમાં unvisited vertexમાંથી સૌથી નાનું tentative distance પસંદ કરો અને તેની outgoing edges relax કરો.

Worked example

Edges (undirected): A–B=4, A–C=1, C–B=2, B–D=1, C–D=5. Source A.

  1. Start: d(A)=0; બીજા બધા ∞.
  2. Aમાંથી: B=4, C=1.
  3. ન્યૂનતમ C=1 finalize; C દ્વારા B=min(4,1+2)=3, D=min(∞,1+5)=6.
  4. હવે B=3 finalize; B દ્વારા D=min(6,3+1)=4.
  5. Final distances: A=0, C=1, B=3, D=4.
relax(u,v): d[v] = min(d[v], d[u] + w(u,v))
MCQ alert: Dijkstra negative-weight edges માટે યોગ્ય નથી. Non-negative weights જરૂરી છે.

5. Fractional Knapsack

વસ્તુનો ભાગ લઈ શકાય છે. દરેક item માટે ratio = profit / weight ગણો; ratioના ઉતરતા ક્રમમાં items લો, bag ભરાય તો છેલ્લી વસ્તુનો જરૂરી fraction લો.

Demo items: (profit,weight) = (60,10), (100,20), (120,30).

Time: O(n log n) due to sorting ratios

ધ્યાન: Fractional Knapsackમાં Greedy optimal છે; 0/1 Knapsackમાં item તોડી શકાતો નથી, તેથી સામાન્ય રીતે DP/અન્ય પદ્ધતિ જોઈએ.

6. Activity Selection

એક સમયે એક activity કરી શકાય. Maximum compatible activities માટે finish timeના વધતા ક્રમમાં sort કરો; જે activityનું start time છેલ્લી પસંદ activityના finish પછી કે બરાબર હોય તેને પસંદ કરો.

Example activities (start, finish): A(1,2), B(3,4), C(0,6), D(5,7), E(8,9), F(5,9).

પસંદગી: finish orderમાં A(1,2), B(3,4), D(5,7), E(8,9) → કુલ 4 activities.

Sorted finish times પછી scan: O(n log n); પહેલેથી sorted હોય તો O(n)

7. Job Scheduling with Deadlines

દરેક jobને unit-time slotમાં schedule કરાય; deadline પહેલાં પૂર્ણ થાય તો profit મળે. સામાન્ય greedy રીત: profitના ઉતરતા ક્રમમાં jobs ગોઠવો અને દરેક jobને deadline પહેલાંનું સૌથી છેલ્લું ખાલી slot આપો.

ઉદાહરણ: J1(d=2,p=100), J2(d=1,p=40), J3(d=2,p=27), J4(d=1,p=15). Profit order: J1, J2, J3, J4. Slot 2માં J1, slot 1માં J2 → total profit 140.

આ ઉદાહરણમાં દરેક jobનો સમય 1 unit માન્યો છે, જે standard job sequencing model છે.

8. Huffman Coding

Frequency મુજબ variable-length prefix codes બનાવે છે. સૌથી ઓછી frequencyના બે nodes વારંવાર જોડો; જોડાયેલ frequency તેમનો સરવાળો છે. અંતે બનેલા treeની દરેક left/right edgeને 0/1 આપો.

Example frequencies

A:5, B:9, C:12, D:13, E:16, F:45.

  1. A(5)+B(9)=14
  2. C(12)+D(13)=25
  3. 14+E(16)=30
  4. 25+30=55
  5. F(45)+55=100 (root)

આ એક માન્ય Huffman treeમાં Fને 0, બાકીના subtreeને 1 આપી આગળ branch કરી શકાય. સમાન frequencyમાં અલગ tree/codes મળી શકે, પણ weighted path length optimal રહે છે.

Prefix-free એટલે કોઈ characterનો code બીજા characterના codeનો prefix નથી; decoding ambiguity થતી નથી.

9. Quick Revision + MCQs

  • MSTમાં V−1 edges અને cycle નથી.
  • Kruskal: sort edges; Prim: grow tree from a vertex.
  • Dijkstra: single-source, non-negative weights.
  • Fractional Knapsack: profit/weight ratio.
  • Activity Selection: earliest finish time first.
  • Job Scheduling: high profit first, latest free slot before deadline.
  • Huffman: combine two lowest frequencies repeatedly.
MCQ 1: MSTમાં V vertices હોય તો edges કેટલી?જવાબ: V−1.
MCQ 2: Negative edge weight માટે Dijkstra વાપરી શકાય?જવાબ: નહીં, standard Dijkstra માટે weights non-negative હોવા જોઈએ.
MCQ 3: Fractional Knapsackમાં items કયા ratioથી sort થાય?જવાબ: Profit / Weightના decreasing orderમાં.
MCQ 4: Huffman algorithm દરેક વખતે શું જોડે છે?જવાબ: સૌથી ઓછી frequency ધરાવતા બે nodes.
