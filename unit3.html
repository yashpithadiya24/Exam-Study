1. Routing — URLથી Action સુધી

Routing: incoming HTTP requestના URL અને HTTP methodને યોગ્ય controller/action અથવા endpoint સાથે match કરવાની પ્રક્રિયા.

Attribute routingConventional routing
Route attributes controller/action પાસે લખાય.એક common route pattern configurationમાં લખાય.
Web APIs માટે સ્પષ્ટ અને resource-based.MVC-style controllers માટે સામાન્ય.
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet] public IActionResult GetAll() => Ok();
    [HttpGet("{id:int}")] public IActionResult Get(int id) => Ok(id);
    [HttpPost] public IActionResult Create() => Created("/api/products/1", null);
}
// Conventional MVC route example:
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

2. Model Binding અને Binding Sources

Model binding HTTP requestમાંથી મળતા valuesને action parameters અથવા C# model propertiesમાં ફેરવે છે.

AttributeData sourceExample URL/request
[FromRoute]URL path/api/products/7
[FromQuery]Query string/api/products?page=2
[FromBody]Request body (JSON){"name":"Pen"}
[FromHeader]HTTP headerX-Client: web
[FromForm]Form data / uploadmultipart/form-data
[HttpGet("{id:int}")]
public IActionResult Get(
    [FromRoute] int id,
    [FromQuery] string? search,
    [FromHeader(Name = "X-Client")] string? client)
{
    return Ok(new { id, search, client });
}

public class CreateStudentRequest
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}
[HttpPost]
public IActionResult Create([FromBody] CreateStudentRequest request)
    => Ok(request);
મેમરી: Route = pathમાં, Query = ? પછી, Body = JSON payload, Header = request metadata, Form = upload/form.

3. Validation: Data Annotations અને FluentValidation

Validation તપાસે છે કે input required rules મુજબ છે કે નહીં. Invalid input database/business logic સુધી પહોંચે તે પહેલાં રોકવું જોઈએ.

Data Annotations

using System.ComponentModel.DataAnnotations;
public class ProductRequest
{
    [Required]
    [StringLength(60, MinimumLength = 2)]
    public string Name { get; set; } = "";

    [Range(1, 100000)]
    public decimal Price { get; set; }

    [EmailAddress]
    public string? ContactEmail { get; set; }
}
AttributeRule
[Required]value જરૂરી.
[StringLength(60)]string length limit.
[Range(1,100)]number range.
[EmailAddress]email format.
[RegularExpression("...")]pattern matching.

FluentValidation

using FluentValidation;
public class StudentRequest
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
    public string Email { get; set; } = "";
}
public class StudentValidator : AbstractValidator<StudentRequest>
{
    public StudentValidator()
    {
        RuleFor(x => x.Name).NotEmpty().MinimumLength(2);
        RuleFor(x => x.Age).InclusiveBetween(16, 80);
        RuleFor(x => x.Email).NotEmpty().EmailAddress();
    }
}
Data AnnotationsFluentValidation
Attributes model properties પર.અલગ validator class અને fluent rules.
સરળ, સામાન્ય rules માટે અનુકૂળ.જટિલ/conditional rules અને reusable validation માટે વધુ expressive.

Custom validation attributeનો વિચાર: ValidationAttribute inherit કરો અને IsValid() override કરીને true/false અથવા ValidationResult આપો. Source question bankમાં આ concept પૂછાય છે; implementationમાં custom ruleનું logic લખવું પડે.

Validation યાદ રાખો: Required = ખાલી નહીં; Range = હદમાં; StringLength = લંબાઈ; EmailAddress = format.

4. API Versioning

API versioningથી નવા clients માટે નવી contract/behavior આપી શકાય અને જૂના clientsને તરત તોડ્યા વગર support કરી શકાય.

Client v1
→
/api/v1/products
→
Version 1 endpoint

Client v2
→
/api/v2/products
→
Version 2 endpoint

મુખ્ય approaches: URL segment (/api/v1/products), query string (?api-version=1.0), header-based versioning. Uploaded notesમાં URL-based versioning પર ખાસ ભાર છે.

// URL segment pattern concept
[Route("api/v1/products")]
public class ProductsV1Controller : ControllerBase { }

// v2 can use a different route/contract
[Route("api/v2/products")]
public class ProductsV2Controller : ControllerBase { }

વાસ્તવિક ASP.NET API Versioning package configuration projectની package/version પ્રમાણે અલગ હોઈ શકે; examમાં approach, URL example અને backward compatibilityનો હેતુ સમજાવો.
