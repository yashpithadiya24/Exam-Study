1. Transport Layer — કામ અને services

Transport Layer અલગ hosts પર ચાલતી application processes વચ્ચે logical end-to-end communication આપે છે. Sender application message ને segmentsમાં વહેંચે છે; receiver segmentsને ફરી messageમાં જોડે છે.

Application message
→
Transport segment
→
Network packet

OSIમાં Transport Layer Layer 4 છે. TCP/IP modelમાં તે સામાન્ય રીતે Application અને Internet/Network layer વચ્ચેનું transport કાર્ય કરે છે.

TCPConnection-oriented, reliable, ordered byte stream; acknowledgement અને retransmission.
UDPConnectionless, નાનો header, ઓછો overhead; delivery/orderની guarantee નથી.

દરેક application process ને port number દ્વારા ઓળખવામાં આવે છે. ઉદાહરણ તરીકે, browser serverના port 80 પર HTTP માટે જોડાઈ શકે છે.

Memory trick: Transport = process-to-process; Network = host-to-host; Data Link = adjacent node-to-node.

2. Multiplexing અને Demultiplexing

Multiplexing (sender): અલગ socketsમાંથી આવેલ data સાથે transport header (source/destination port વગેરે) ઉમેરવું. Demultiplexing (receiver): headerની માહિતીથી segment યોગ્ય socket/application સુધી પહોંચાડવો.

UDP / connectionless સામાન્ય રીતે destination portના આધારે યોગ્ય socket પસંદ થાય છે; અલગ source IP/portથી આવેલા datagrams પણ એક જ destination socket સુધી આવી શકે છે.
TCP / connection-oriented TCP socketને 4-tuple ઓળખે છે: source IP, source port, destination IP, destination port. એક server ઘણા clients માટે અલગ sockets રાખી શકે છે.
ઉદાહરણ: એક જ laptop પર browser, game અને music app એકસાથે network વાપરે છે. Port/socket માહિતીથી આવેલ data યોગ્ય applicationને મળે છે.
Exam point: TCP demultiplexing = 4-tuple; UDP demultiplexingમાં destination port મુખ્ય ઓળખ છે.

3. UDP — User Datagram Protocol

UDP transport-layerનું connectionless protocol છે. Sender connection setup/handshake કર્યા વિના datagram મોકલે છે. Delivery, retransmission, acknowledgement, flow control અને congestion control UDP પોતે guarantee કરતું નથી.

UDP header = 8 bytes = 4 fields × 16 bits
FieldSizeકામ
Source port16 bitsમોકલનાર processનો port
Destination port16 bitsપ્રાપ્ત કરનાર processનો port
Length16 bitsHeader + dataની કુલ length (bytes)
Checksum16 bitsError detect કરવામાં મદદ

PDFમાં આપેલા ઉપયોગો: DNS, SNMP, RIP, online gaming અને multimedia streaming જેવી loss-tolerant અથવા rate-sensitive applications.

UDP checksum

Sender segmentને 16-bit words તરીકે ગણે છે, one’s-complement addition કરે છે અને checksum મૂકે છે. Receiver ફરી ગણતરી કરીને તપાસે છે; mismatch હોય તો error detect થાય છે. Checksum error detect કરે છે, delivery guarantee નથી આપતું.

યાદ રાખો: UDP = Quick, Unconnected, Delivery not guaranteed. Header sizeનો MCQ જવાબ 8 bytes.

4. Reliable Data Transfer (RDT)

Reliable transferનો હેતુ: data પહોંચે, duplicate ન થાય, યોગ્ય orderમાં રહે અને bit errors handle થાય. Unreliable channelમાં bit error અથવા packet/ACK loss થઈ શકે છે.

Protocolમુખ્ય સુધારો
rdt 1.0Perfect channel: error/loss નથી માનતા
rdt 2.0Bit errors માટે ACK/NAK
rdt 2.1Sequence numberથી duplicate ઓળખે
rdt 2.2NAK વગર, ACK-only approach
rdt 3.0Packet/ACK loss માટે timeout અને retransmission

ACK: packet મળ્યાની પુષ્ટિ. NAK: error/સાચો packet ન મળ્યાનો સંકેત. Sequence number: duplicate અથવા યોગ્ય ક્રમ ઓળખે. Timeout: સમયસર ACK ન મળે તો ફરી મોકલવું.

Sender: packet મોકલે
→
Receiver: તપાસે
→
ACK / NAK
→
Sender next step
Mnemonic: 1.0 perfect; 2.x bit errors; 3.0 loss.

5. Stop-and-Wait, Sliding Window, Go-Back-N અને Selective Repeat

Stop-and-Wait: એક packet મોકલો, ACKની રાહ જુઓ, પછી આગળનો મોકલો. સરળ છે, પરંતુ લાંબા delayવાળા linkમાં utilization ઓછી થઈ શકે છે.

Pipelining / Sliding Window: ACK આવે તે પહેલાં અનેક packets મોકલવાની મંજૂરી. Windowમાં કેટલા unacknowledged packets હોઈ શકે તે મર્યાદિત છે.

મુદ્દોGo-Back-N (GBN)Selective Repeat (SR)
Lost/error packetખોવાયેલા packetથી પછીના જરૂરી packets ફરી મોકલાયમાત્ર ગુમ/ખોટા packetને ફરી મોકલે
Receiverસામાન્ય રીતે in-order packet સ્વીકારે; out-of-order discardOut-of-order packets buffer કરી શકે
Complexityઓછીવધુ
Retransmissionવધુ packets ફરી જવા શકેસામાન્ય રીતે કાર્યક્ષમ
Example: Packet 2 ખોવાય અને 3,4 પહોંચે. GBNમાં 2 પછીના packets ફરી મોકલવા પડી શકે; SRમાં 2 ફરી મોકલાય અને 3,4 buffer થઈ શકે.
Exam distinction: GBN = go back and retransmit from missing packet; SR = retransmit selectively.

6. TCP — Connection-oriented transport

TCP reliable, in-order, connection-oriented byte-stream service આપે છે. મુખ્ય features: sequence numbers, acknowledgements, checksum, retransmission, flow control અને congestion control.

Three-way handshake

Client → SYN
→
Server → SYN + ACK
→
Client → ACK

Handshake પછી data transfer શરૂ થાય છે. Connection બંધ કરતી વખતે TCP termination exchange કરે છે.

TCP headerના મુખ્ય fields

  • Source / Destination port
  • Sequence number અને Acknowledgement number
  • Header length, flags (SYN, ACK, FIN વગેરે)
  • Receive window (flow control)
  • Checksum, urgent pointer/options
TCPUDP
Connection setupConnection setup નથી
Reliable, orderedBest-effort; ordering guarantee નથી
Header minimum 20 bytesHeader 8 bytes
વધુ control/overheadઓછો overhead
યાદ રાખો: TCP = handshake + reliability + order; UDP = lightweight + no built-in retransmission.

7. Flow Control

Flow control senderને એટલી ઝડપે data મોકલવા કહે છે કે receiverની buffer ક્ષમતા overflow ન થાય. એટલે આ receiverને protect કરે છે.

TCPમાં receiver advertised window (rwnd) દ્વારા કેટલી additional data સ્વીકારી શકે તે જણાવે છે. Sender એ મર્યાદા ધ્યાનમાં રાખીને outstanding data રાખે છે.

Flow controlSenderની ઝડપ સામે receiverની capacityનું સંચાલન.
Congestion controlNetworkમાં routers/links પર વધારે trafficથી થતી ભીડનું સંચાલન.
MCQ trap: Flow control networkને નહીં, મુખ્યત્વે receiverને overload થવાથી બચાવે છે.

8. Congestion Control અને TCP Slow Start

Congestion ત્યારે થાય છે જ્યારે networkમાં આવતો traffic routers/linksની capacity કરતાં વધારે થાય. પરિણામે queueing delay, packet loss અને retransmissions વધી શકે છે.

PDFમાં congestion-control approachesને broad રીતે end-to-end અને network-assisted વિચારો તરીકે સમજાવવામાં આવે છે. TCP congestion controlમાં sender congestion window (cwnd) વડે in-flight data નિયંત્રિત કરે છે.

TCP Slow Start

Connection શરૂઆતમાં congestion window નાની રાખે છે અને ACK મળતાં window ઝડપથી વધે છે, જ્યાં સુધી threshold અથવા congestionનો સંકેત ન મળે. ત્યારબાદ congestion-avoidance વર્તન લાગુ થઈ શકે છે.

9. RPC અને Quick Revision / MCQ

RPC (Remote Procedure Call) એ communication method છે જેમાં program જાણે local function call કરે તેમ બીજા computer પર procedure/function execute કરાવી શકે છે. RPC પોતે transport protocol નથી; તે TCP/UDP જેવા transportનો ઉપયોગ કરી શકે છે.

એક નજરમાં

  • Transport layer = process-to-process communication.
  • UDP header = 8 bytes; TCP minimum header = 20 bytes.
  • TCP handshake = SYN → SYN-ACK → ACK.
  • rdt 2.0 bit error, rdt 3.0 packet/ACK loss handle કરે છે.
  • GBNમાં missing packetથી આગળના packets ફરી મોકલાઈ શકે; SR selective retransmission કરે છે.
  • Flow control receiverને બચાવે; congestion control networkને.
Q1. UDP header size કેટલી છે?

જવાબ: 8 bytes.

Q2. TCP socket કયા tupleથી ઓળખાય છે?

જવાબ: 4-tuple — source IP/port અને destination IP/port.

Q3. Packet loss માટે timeout/retransmission કયા RDTમાં આવે છે?

જવાબ: rdt 3.0.

Q4. Receiver buffer overflow અટકાવતી પદ્ધતિ?

જવાબ: Flow control.

Q5. Selective Repeatનો મુખ્ય ફાયદો?

જવાબ: માત્ર lost/error packetને retransmit કરી શકે છે.
