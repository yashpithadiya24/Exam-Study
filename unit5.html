1. Data Link Layer — કામ અને services

Data Link Layer એક link પર physically adjacent nodes વચ્ચે datagramને frame સ્વરૂપે પહોંચાડે છે. Network layerના datagramમાં header/trailer ઉમેરીને frame બનાવવામાં આવે છે.

FramingDatagramને frameમાં encapsulate કરવું; header અને trailer ઉમેરવા.
Link accessShared medium ક્યારે વાપરવો તે નક્કી કરવું; MAC address frameમાં source/destination ઓળખે છે.
Reliable deliveryજરૂર હોય ત્યારે ACK અને retransmissionથી link પર error-free deliveryનો પ્રયાસ.
Flow controlAdjacent sender/receiver વચ્ચે data મોકલવાની ઝડપનું pacing.
Error detectionNoise/attenuationથી થયેલા errors શોધવા.
Error correctionકેટલીક પદ્ધતિમાં retransmission વગર bit error ઓળખી/correct કરી શકાય.

MAC address local link પર interface ઓળખે છે; IP address network-layer addressing માટે છે. બંને એક જ નથી.

યાદ રાખો: Data Link = frame + MAC + local link delivery.

2. Framing — Bit Stuffing અને Byte Stuffing

Framingનો હેતુ frame ક્યાં શરૂ થાય અને ક્યાં પૂરો થાય તેની boundary receiverને સ્પષ્ટ કરવો છે.

Bit Stuffing

Bit-oriented protocolમાં flag pattern 01111110 frame boundary દર્શાવી શકે છે. Dataમાં સતત પાંચ 1 bits આવ્યા પછી sender એક extra 0 insert કરે છે. Receiver આ stuffed 0 કાઢી નાખે છે.

Example: Data run `11111` → transmit થાય `111110` (પાંચ 1 પછી stuffed 0). આથી data flag sequence સાથે ગૂંચવાતું નથી.

Byte Stuffing

Byte-oriented protocolમાં FLAG byte frame boundary બતાવે છે. જો dataની અંદર FLAG જેવી value આવી જાય, તો sender તેની પહેલાં ESC (escape) byte ઉમેરે છે. Receiver data deliver કરતાં પહેલાં ESC દૂર કરે છે.

મુદ્દોBit stuffingByte stuffing
Data unitBitsBytes
Insert શું થાય?5 consecutive 1 પછી 0FLAG/ESC જેવા special byte પહેલાં ESC
ReceiverStuffed 0 remove કરેEscape byte remove કરે
MCQ trick: Bit stuffing → 5 ones પછી 0; Byte stuffing → FLAG પહેલાં ESC.

3. Error Detection — Parity, Checksum, CRC

Parity Check

Original bits સાથે એક parity bit ઉમેરાય છે. Even parityમાં કુલ 1sની સંખ્યા even બનાવાય; odd parityમાં odd. Single-bit flip detect થઈ શકે, પરંતુ અનેક bit errorsમાં કેટલાક patterns ચૂકી શકે.

Example: Data `1001`માં બે 1 છે. Even parity માટે parity bit `0` → `10010` (કુલ 1s = 2, even). Dataમાં 1sની સંખ્યા odd હોય તો even parity માટે bit `1` ઉમેરાય.

Checksum

  1. Dataને સમાન કદના words/segmentsમાં વહેંચો.
  2. One’s-complement arithmeticથી ઉમેરો; carry બહાર જાય તો પાછો ઉમેરો (wraparound).
  3. Sumના bits complement કરીને checksum બનાવો.
  4. Receiver ફરી ઉમેરે અને પરિણામથી error તપાસે.

CRC — Cyclic Redundancy Check

CRC binary modulo-2 division અને XOR આધારિત છે. Generator polynomialના degree r માટે dataના અંતે r zero ઉમેરો, divide કરો, remainderને data સાથે append કરો. Receiver એ જ divisorથી divide કરે: remainder zero હોય તો error detect ન થયું; non-zero remainder હોય તો corruption સૂચવે છે.

CRC appended bits = division remainder; zero remainder → frame accepted (PDFની સમજ પ્રમાણે)
PDF example: Data `100100`, generator polynomial \(x^3+x^2+1\), divisor `1101`; degree 3 હોવાથી 3 zeros append કરીને `100100000` પર modulo-2 division કરો. મળેલ remainder dataના અંતે ઉમેરાય.
Techniqueમુખ્ય વિચાર
Parity1sની even/odd count
ChecksumOne’s-complement sum + complement
CRCModulo-2 binary division / XOR remainder
યાદ રાખો: P-C-C = Parity counts, Checksum adds, CRC divides.

4. Multiple Access — Shared Channel

Point-to-point linkમાં એક sender અને એક receiver હોય છે. Broadcast/shared linkમાં ઘણા nodes એક જ channel share કરે છે. એક જ સમયે ઘણા nodes મોકલે તો collision થઈ શકે.

Multiple Access Protocol એ shared communication channel ક્યારે અને કેવી રીતે વાપરવો તેના નિયમો છે.

Channel partitioningChannelને time, frequency અથવા codeમાં વહેંચે. TDMA, FDMA, CDMA.
Random accessNode મોકલવાનો પ્રયાસ કરે; collision થઈ શકે અને recovery rules હોય. ALOHA, CSMA.
Taking turnsNodes ક્રમથી turn લે. Polling, Token Passing.
Memory trick: P-R-T = Partition, Random, Taking turns.

ProtocolResource divisionકામ કરવાની રીતમર્યાદા
TDMATime slotsસમયને frames/slotsમાં વહેંચે; દરેક nodeને slotNode પાસે data ન હોય તો slot idle; પોતાની turnની રાહ
FDMAFrequency bandsદરેક nodeને અલગ frequency bandકોઈ band વપરાતો ન હોય તો resource idle
CDMAUnique codeદરેક node પોતાના codeથી data encode કરે; receiver codeથી અલગ પાડેયોગ્ય code design/processing જરૂરી

TDMA example: 6 stations અને 6 slots હોય; station 1, 3, 4 પાસે data હોય તો તેમના slots વપરાય અને બાકીના slots ખાલી રહી શકે.

Exam shortcut: T = Time, F = Frequency, C = Code.

6. ALOHA, CSMA/CD અને CSMA/CA

Pure ALOHA અને Slotted ALOHA

Pure ALOHA: data હોય ત્યારે કોઈપણ સમયે transmit કરે; overlapથી collision થઈ શકે. Vulnerable time = 2T, જ્યાં T એક frame transmission time છે.

Slotted ALOHA: સમય slotsમાં વહેંચાય છે અને transmission slotની શરૂઆતમાં જ થાય છે. Vulnerable time = T; એટલે Pure ALOHA કરતાં collision risk ઘટાડે છે.

Pure ALOHA vulnerable time = 2T
Slotted ALOHA vulnerable time = T

CSMA family

CSMA: transmit કરતા પહેલાં channel sense કરે—ખાલી લાગે તો મોકલવાનો પ્રયાસ. છતાં propagation delayને કારણે collision થઈ શકે.

CSMA/CD: Collision Detection; Ethernetના traditional shared wired mediumમાં collision detect કરીને transmission અટકાવવાની/ recoveryની રીત.

CSMA/CA: Collision Avoidance; Wi‑Fi જેવા wireless mediumમાં collision થવાની શક્યતા ઘટાડવાનો પ્રયાસ. Wirelessમાં transmit કરતી વખતે પોતાનો signal હોવાથી collision detect કરવું મુશ્કેલ છે.

ProtocolVulnerable time / focusયાદ રાખો
Pure ALOHA2TAnytime transmit
Slotted ALOHATSlotની શરૂઆતમાં transmit
CSMA/CDCollision detectionTraditional wired Ethernet

MCQ trick: Pure = 2T, Slotted = T; CD = Detect (wired), CA = Avoid (wireless).

7. Polling, Token Passing અને Ethernet

Polling

એક master node બાકીના nodesને round-robin રીતે પૂછે છે કે કોણ transmit કરી શકે. Collisions અને ખાલી slots ઘટાડે છે, પરંતુ polling overhead અને master failureનો મુદ્દો હોઈ શકે.

Token Passing

અહીં master જરૂરી નથી. Special frame એટલે token નિશ્ચિત ક્રમમાં nodes વચ્ચે ફરે છે. Token મળેલો node data હોય તો transmit કરે; નહીં તો આગળ મોકલે. Token ગુમાવવો અથવા node failure મુશ્કેલી ઊભી કરી શકે.

Ethernet

Ethernet વ્યાપક LAN technology છે. PDFમાં ઉલ્લેખિત versions:

TypePDFમાં આપેલી speedમુખ્ય નોંધ
Switched Ethernet10 Mbps per port (PDFની slide મુજબ)દરેક switch port સાથે device/segment જોડાય
Fast Ethernet100 MbpsEthernet frame format સાથે high data rate
Gigabit Ethernet1 GbpsFiber અને ટૂંકા અંતરે copper વિકલ્પો

Switch સામાન્ય રીતે MAC address table શીખીને LANમાં યોગ્ય port તરફ frame મોકલે છે. (આ પેજમાં switchનો basic context છે; VLANની વિગત અપલોડ કરેલા slide textમાં સ્પષ્ટ રીતે મળી નથી.)

8. ARP (Address Resolution Protocol) + Quick Revision

ARP IPv4 addressને local networkમાં વપરાતા MAC/physical address સાથે map કરે છે. ARP cacheમાં IP ↔ MAC mapping રાખવામાં આવે છે.

Cacheમાં entry ન હોય તો host LAN પર ARP Request broadcast કરે છે. પોતાનો IP ઓળખતો host ARP Reply આપે છે. Sender cache update કરીને frameને યોગ્ય MAC address પર મોકલે છે.

ઝડપી યાદગીરી

  • Frame boundary માટે framing.
  • Bit stuffing: પાંચ સતત 1 પછી 0 ઉમેરો.
  • Byte stuffing: special FLAG/ESC પહેલાં ESC ઉમેરો.
  • Parity counts 1s; checksum adds words; CRC binary division/XOR.
  • TDMA time, FDMA frequency, CDMA code.
  • Pure ALOHA vulnerable time 2T; Slotted ALOHA T.
  • Pollingમાં master; Token passingમાં token, master નથી.
  • ARP IPv4 addressને MAC address સાથે map કરે છે.
Q1. Bit stuffingમાં 0 ક્યારે ઉમેરાય?

જવાબ: પાંચ સતત 1 bits પછી.

Q2. Byte stuffingમાં dataની અંદર FLAG આવે તો શું ઉમેરાય?

જવાબ: ESC byte.

Q3. CRC કઈ operation પર આધારિત છે?

જવાબ: Modulo-2 binary division / XOR.

Q4. Pure ALOHAનું vulnerable time?

જવાબ: 2T.

Q5. IP addressથી MAC address મેળવવામાં કયો protocol મદદ કરે છે?

જવાબ: ARP.
