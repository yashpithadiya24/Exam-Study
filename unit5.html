1. Graph Basics

Graph G=(V,E)માં V vertices/nodes અને E edges છે. Directed edgeમાં direction હોય છે; undirected edgeમાં direction નથી. Weighted graphની edges પર cost/weight હોય છે.

Directed

A → B અને B → A અલગ edges હોઈ શકે.

Undirected

A—Bમાં બંને દિશામાં connection માનવામાં આવે છે.

Applications: road maps, social networks, web links, resource-allocation/deadlock graphs, dependency networks.

Connected components

Undirected graphનો connected component એવો maximal subgraph છે જેમાં દરેક pair વચ્ચે path હોય. Directed graph strongly connected ત્યારે કહેવાય જ્યારે દરેક vertexથી દરેક બીજા vertex સુધી directed path હોય.

Articulation Point

એવો vertex જેને દૂર કરતાં connected componentsની સંખ્યા વધે તે articulation point. તે networkનું single point of failure બતાવી શકે છે.

2. DFS vs BFS

DFS (Depth First Search): એક pathમાં શક્ય તેટલું ઊંડે જાય; પછી backtrack કરે. Recursion અથવા stack વાપરે.

BFS (Breadth First Search): level by level traversal કરે. Queue વાપરે; unweighted graphમાં shortest path (fewest edges) શોધે.

Interactive traversal

Graph: A connects B,C; B connects D,E; C connects F. Neighbours alphabetical orderમાં જુઓ.

DFS order adjacency order પ્રમાણે બદલાઈ શકે છે. Examમાં graphના edges અને neighbour visitation order સ્પષ્ટ લખો.

3. Topological Sorting

DAG (Directed Acyclic Graph)નું linear ordering જેમાં દરેક directed edge u→v માટે u, v પહેલાં આવે. Kahn methodમાં indegree 0 vertex પસંદ કરો, outputમાં ઉમેરો અને તેની outgoing edges દૂર કરો; indegree ફરી update કરો.

  1. દરેક vertexનો indegree ગણો.
  2. Indegree 0 verticesને queueમાં મૂકો.
  3. એક vertex કાઢો, outputમાં ઉમેરો; neighboursના indegree ઘટાડો.
  4. કોઈ neighbourનો indegree 0 થાય તો queueમાં ઉમેરો.

જો બધા vertices outputમાં ન આવે તો graphમાં cycle છે; topological order અસ્તિત્વમાં નથી.

4. Backtracking & N-Queens

Backtracking recursive search છે: એક candidate પસંદ કરો, constraint તૂટે અથવા solution ન મળે તો decision undo કરીને બીજી choice અજમાવો. State-space treeમાં depth-first રીતે search થાય છે.

N-Queens: N×N chessboard પર N queens એવી રીતે મૂકો કે કોઈ બે એક જ row, column અથવા diagonalમાં ન હોય. સામાન્ય રીતમાં દરેક rowમાં એક queen મૂકી safe column શોધો.

4-Queens: valid solution visualization

એક valid arrangement: row-wise columns = [2,4,1,3].

દરેક rowમાં એક queen છે; કોઈ pair સમાન column કે diagonalમાં નથી.

Promising state: અત્યાર સુધી મૂકેલી queens એકબીજાને attack કરતી નથી, એટલે આગળ search ચાલુ રાખી શકાય.

5. Branch & Bound

Branch & Bound optimization માટે state-space treeમાં branches બનાવે છે અને boundથી કોઈ branchનો best possible result પણ હાલના best કરતાં ખરાબ હોય તો તેને prune કરે છે.

BacktrackingBranch & Bound
મુખ્યત્વે constraints/feasibilityથી invalid branch કાપે.Objective value અને boundથી suboptimal branch કાપે.
ઘણીવાર DFS.DFS, BFS અથવા best-first selection થઈ શકે.
ઉદાહરણ: N-Queens.ઉદાહરણ: Knapsack optimization.

Knapsack using Branch & Bound

Nodesમાં item include/exclude decisions રાખો. Bound ગણવા fractional knapsack relaxation વાપરી શકાય. જો nodeનો upper bound ≤ best known profit હોય, branch explore કરવાની જરૂર નથી.

Minimax principle: two-player zero-sum game treeમાં MAX player maximum child value પસંદ કરે; MIN player minimum child value પસંદ કરે. Tic-Tac-Toeમાં જીત = +1, draw = 0, હાર = −1 તરીકે મૂલ્યાંકન કરી શકાય.

MAX: max(child values) · MIN: min(child values)

6. String Matching — Naive Algorithm

Text T length n અને pattern P length m. Patternને દરેક possible alignment પર મૂકી character-by-character compare કરો. Match થાય તો starting index report કરો.

Worst-case time: O((n−m+1)m) = O(nm) · Extra space O(1) (excluding output)

7. Rabin–Karp Algorithm

Pattern અને દરેક text windowનો hash ગણાય. Hash અલગ હોય તો actual match નથી; hash સમાન હોય ત્યારે characters verify કરો, કારણ કે collision શક્ય છે.

  1. Patternનું hash compute કરો.
  2. Textની પ્રથમ m-length windowનું hash ગણો.
  3. Hash match થાય તો characters verify કરો.
  4. Rolling hashથી આગલી windowનું hash ઝડપથી update કરો.

Complexity: Average/expected O(n+m) યોગ્ય hashing assumptions હેઠળ; worst-case O(nm) collisionsને કારણે.

Rabin–Karpનું મુખ્ય keyword: hash + rolling hash + verify collision.

8. Finite Automata String Matching

Pattern માટે finite-state machine બનાવાય છે. State q દર્શાવે છે કે patternના કેટલા પ્રારંભિક characters હાલ સુધી match થયા છે. દરેક text character પર transition functionથી next stateમાં જાઓ; accepting state પર pattern match થયો.

State q = matched prefix length · Transition: δ(q, character)

Automaton pre-processing pattern અને alphabet પર આધારિત છે; પછી text scan સામાન્ય રીતે O(n)માં થાય. Transition table પહેલેથી બનાવવી પડે.

9. Knuth–Morris–Pratt (KMP)

KMP mismatch થાય ત્યારે text pointerને પાછળ લઈ જતું નથી. LPS / prefix function (Longest Proper Prefix which is also Suffix)થી જાણે છે કે કેટલા matched characters ફરી ઉપયોગ કરી શકાય.

  1. Pattern માટે LPS array બનાવો.
  2. Text અને pattern pointersથી આગળ વધો.
  3. Match થાય તો બંને pointers આગળ.
  4. Mismatch પછી j>0 હોય તો j=LPS[j−1]; નહીં તો text pointer આગળ.

Classસરળ અર્થExam keyword
PPolynomial timeમાં solve કરી શકાય.Efficiently solvable (deterministic model)
NPCandidate solution સાચું છે કે નહીં તે polynomial timeમાં verify કરી શકાય.Polynomial verification
NP-CompleteNPમાં છે અને દરેક NP problemથી polynomial-time reduction છે.In NP + NP-hard
NP-Hardદરેક NP problem જેટલું કઠિન અથવા વધુ; NPમાં હોવું જરૂરી નથી.May not be in NP

જો કોઈ NP-Complete problem માટે polynomial-time algorithm મળે, તો P=NP થાય. હાલ P=NP છે કે નહીં તે અજ્ઞાત છે.

Memory trick: NP-Complete = NP + Hard; NP-Hard માટે solution verification polynomial timeમાં થાય જ એવું જરૂરી નથી.

11. Quick Revision + MCQs

  • DFS = stack/recursion; BFS = queue.
  • Topological sort માત્ર DAG માટે.
  • Articulation point કાઢતાં components વધે.
  • Backtracking constraintsના આધારે; Branch & Bound objective boundના આધારે prune કરે.
  • Naive matching worst O(nm); KMP O(n+m).
  • Rabin–Karp hash uses; collisions verify કરવા પડે.
  • NP-Complete problems NPમાં પણ છે અને NP-Hard પણ છે.
