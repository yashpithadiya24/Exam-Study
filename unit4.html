1. API Security અને Authentication vs Authorization

APIમાં student records, accounts, financial અને administrative data હોઈ શકે છે. Security ન હોય તો unauthorized access, data leakage અને misuse થઈ શકે.

AuthenticationAuthorization
“તમે કોણ?” — user identity verify કરે.“તમને શું કરવાની છૂટ?” — permissions check કરે.
Login, password, token validation.Roles, policies, claims.
સામાન્ય failure: 401 Unauthorized.સામાન્ય failure: 403 Forbidden.
Memory trick: AuthenTICation = identity/ID check; AuthorIZation = permission/zone check.

2. JWT (JSON Web Token)

JWT signed token છે, જે client request સાથે મોકલે છે જેથી API token validate કરીને user claims ઓળખી શકે. JWT પોતે આપમેળે encrypted હોવો જરૂરી નથી; payload સામાન્ય રીતે decode કરી શકાય, એટલે તેમાં secret/password ન મૂકવા.

  • Header: token type અને signing algorithm.

ASP.NET Core configuration concept

builder.Services.AddAuthentication("Bearer")
    .AddJwtBearer("Bearer", options =>
    {
        options.TokenValidationParameters = new()
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = builder.Configuration["Jwt:Issuer"],
            ValidAudience = builder.Configuration["Jwt:Audience"],
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(builder.Configuration["Jwt:Key"]!))
        };
    });

builder.Services.AddAuthorization();
app.UseAuthentication();
app.UseAuthorization();

Productionમાં strong secret configuration/secretsમાં રાખો, expiry validate કરો, HTTPS વાપરો અને signing key source codeમાં hardcode ન કરો. Authentication middleware, Authorization middleware પહેલાં આવે.

3. Role-based અને Policy-based Authorization

Role-based: userને Admin, Teacher, Student જેવા roleના આધારે access. Policy-based: એક અથવા વધુ claims/requirements પર rule આધારિત access.

[Authorize]
[HttpGet("profile")]
public IActionResult Profile() => Ok();

[Authorize(Roles = "Admin")]
[HttpDelete("{id:int}")]
public IActionResult Delete(int id) => NoContent();

[Authorize(Policy = "CanManageProducts")]
[HttpPost]
public IActionResult Create() => Ok();

// Program.cs
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("CanManageProducts",
        policy => policy.RequireRole("Admin")
                        .RequireClaim("permission", "products.write"));
});
Role-basedPolicy-based
સરળ role namesથી access.Roles, claims અને custom requirements combine કરી શકે.
[Authorize(Roles="Admin")][Authorize(Policy="CanManageProducts")]
Role structure સરળ હોય ત્યારે.Fine-grained/complex access rules માટે.

4. Refresh Token

Access token સામાન્ય રીતે ટૂંકા સમય માટે valid હોય છે. Refresh token વધુ સમય માટે રાખી શકાય અને access token expire થાય ત્યારે નવો access token મેળવવા વપરાય.

Login
→
Access + Refresh token
→
Access token expires
→
Refresh token serverને
→
New access token
  • Refresh token secure રીતે store કરો; તેને access tokenની જેમ public/logમાં ન મૂકવો.
  • Server-side revoke/rotation વિચારવો, ખાસ કરીને logout અથવા token compromise થાય ત્યારે.
  • Expired/invalid refresh token હોય તો ફરી login જરૂરી બની શકે.
યાદ રાખો: Access token = API access માટે short-lived key; Refresh token = નવો access token મેળવવાનો credential.

5. CORS, HTTPS Redirection અને HSTS

CORS (Cross-Origin Resource Sharing): browserને અલગ origin (scheme + host + port) પરથી API call કરવાની permission policy. CORS authentication નથી; તે browserનું cross-origin access નિયંત્રિત કરે છે.

builder.Services.AddCors(options =>
{
    options.AddPolicy("FrontendOnly", policy =>
        policy.WithOrigins("https://app.example.com")
              .AllowAnyHeader()
              .AllowAnyMethod());
});

app.UseCors("FrontendOnly");

Specific trusted origin આપો. Credentials/ cookies સાથે broad wildcard origin ન વાપરો. CORS browser security policy છે; Postman/server-to-server request પર browser જેવી રીતે લાગુ પડતું નથી.

  • HTTPS redirection: HTTP requestને HTTPS તરફ redirect કરે, જેથી transport encrypted રહે.
  • HSTS: browserને નિર્ધારિત સમય સુધી આ site માટે HTTPS જ વાપરવા કહે છે.
if (!app.Environment.IsDevelopment())
{
    app.UseHsts();
}
app.UseHttpsRedirection();

6. ASP.NET Core Identity અને Secure API checklist

ASP.NET Core Identity: user accounts, passwords, roles, claims, login અને account management માટે framework system.

Input validation
Range/format/length તપાસો; server-side validation જરૂરી.
HTTPS
Transitમાં data encrypt કરો.
Least privilege
જેટલી permission જરૂરી એટલી જ આપો.
Secrets management
Keys/passwords repoમાં commit ન કરો.
Token hygiene
Expiry, signature, issuer, audience validate કરો.
Safe errors/logs
Secrets અને sensitive data response/logમાં ન નાખો.
Secure API practices માટે examમાં લખો: HTTPS, input validation, authentication, role/policy authorization, safe secret storage, CORS allowlist, token expiry/signature validation, least privilege અને security logging/rate limiting where appropriate.
Short memory: H-V-A-T-C-L = HTTPS, Validation, Authentication, Token checks, CORS, Least privilege.
